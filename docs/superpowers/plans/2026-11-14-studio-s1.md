# Hierarchical Chip Studio S1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver a usable local hierarchical model workbench with a real CPU shared-encoder experiment, editable chips, Python round-trip and measured probes.

**Architecture:** A new `studio` client uses a UI-independent Python document and executor, with a separate HTTP coordinator and per-run worker process. The selected direction is slide 5, “方案3：层级芯片”, in the delivered PPT; original ML Forge screenshot supplies dark engineering visual tokens. This is an original implementation of that selected direction, not a claim of pixel fidelity to unavailable generated mockups.

**Tech Stack:** Product Design React/Vite starter, React Flow for editable computational graph, Phosphor icons, Python standard-library HTTP/process coordination, CPU PyTorch.

**Spec:** `docs/可视化AI架构设计与实验仿真平台项目计划书.md`; S1 contract in `studio/CONTRACT.md`.

## Global Constraints

- Do not modify the original `ml_forge` business modules.
- Real tensor/loss/gradient/update values; no demonstration metrics presented as observations.
- Graph import never executes uploaded Python; unsupported syntax fails explicitly.
- Preserve instance sharing, chip definitions, named values and root outputs in graph/code conversion.
- Server state, run artifacts and logs stay under `studio`; browser drafts use localStorage, and QA captures are saved under `output/playwright`. No deployment or large model/data downloads.
- No Git checkout exists; do not invent commits or initialize an unrelated repository. Keep source baseline evidence and review changes by file.
- Product Design owns the frontend starter; preserve its Vite/Sites runtime and use local API proxy.
- Same graph schema is used by client, validator, exporter and execution worker.
