# S4 桌面交付收口计划

日期：2026-11-18。基线：`a4a3315`，ModelCircuit Studio · 模路。用户已批准开展上轮所列下一步；本轮完成 S4 CPU/CUDA 桌面交付，并编写 S5 设计，不开始实现 S5 算子或训练协议。

## 约束与决策

- 使用现有 CPU/CUDA 环境，不安装依赖、不下载模型或外部数据；诊断只用生成的小样本。
- 保留原 `ml_forge/`、根 LICENSE、S3 固定 EXE 和旧 ZIP；新包单独输出。
- 原生应用形式不变；调试仅用程序自身回调、framebuffer 和独立 worker，不使用电脑控制或浏览器输入自动化。
- 新便携目录及可执行文件采用 ModelCircuitStudio 名称；历史源码标识和旧启动脚本兼容保留。
- CPU/CUDA 构建及显存/原生窗口诊断顺序运行，避免资源争抢；独立只读核查可并行。
- 当前以独立开发分支隔离变更，复用主工作目录中的既有环境与构建缓存。不创建或删除其他工作树，不改主分支。
- 发布范围为本地便携产物；本轮不上传大包、创建 GitHub Release 或公开发布。

## Task A：打包与许可

新增 S4 spec 与构建入口参数，输出 `studio/dist/s4-cpu/ModelCircuitStudio/ModelCircuitStudio.exe` 和 `studio/dist/s4-cuda/ModelCircuitStudio/ModelCircuitStudio.exe`，不覆盖旧固定路径。保留默认旧构建行为的兼容性；新构建显式选择 S4。打入项目 LICENSE、来源声明、torchvision 许可及实际运行依赖的许可/元数据。增加可区分 S4 和 CPU/CUDA 的构建标识。新增清晰的 S4 启动器，缺少构建时准确报错。

验证：构建脚本解析、spec 的资源/隐藏导入、依赖许可实际存在；构建后检查可执行文件及分发目录，不以打包退出成功代替功能验收。

## Task B：S4 冻结诊断

为正式入口新增运行/原生诊断。覆盖 36 项目录与 14 模型入口、hardware-v5、可展开模型、Python 有/无 metadata 往返、v3 页签/分屏保存恢复和本地芯片。通过实际 RunManager→worker 完成一个超过旧参数阈值的模型短分类训练，核查参数更新、结果、checkpoint 与内存报告。保持既有 S3 配对/共享/恢复诊断可运行。原生诊断检查实际注册回调和 framebuffer，不把物理手势当作已验。

验证：新增诊断的错误/设备/清理路径测试；CPU/CUDA backend/native 完整回归；实际冻结 CPU、冻结 CUDA 选 cuda:0、冻结 CUDA 显式选 CPU；报告、退出码与 worker 关闭共同核查。生成诊断数据不作为科研性能证据。

## Task C：集成与交付

仅修改当前应用显示品牌和产品标识，旧工程兼容协议及旧状态目录保持。S4 冻结程序两种入口共用独立的 `ModelCircuitStudio-S4` 状态目录，避免覆盖旧版自动保存；旧项目可显式打开。构建并运行 Task B 的诊断；修复范围内真实失败并复审。归档包采用 `ModelCircuitStudio-Windows-x64-S4-CPU.zip` / `...-CUDA.zip`；完整 CRC、逐项内容、EXE SHA256 与旧 S3 保护哈希核查后才标交付完成。

更新 README、S4 交付说明与交接状态，明确源码/新包/旧包、固定运行设备范围及未验证边界。保留可携带验收记录，原始日志和大产物只留本地。独立审查本轮源码差异及验收证据；无阻断问题且实际诊断通过后再提交开发分支。

## Task D：S5 设计

单独形成 Transformer/ViT 与最小 TaskAdapter 的设计及可执行拆分计划。限定首批可展开 Encoder/ViT、轴/掩码/类型契约、Python 往返和独立数值验证。完整训练关系图、生成、3D、多 GPU 不假装在此实现。此任务只写文档，不启动下一阶段构建。

## 退出关口

本轮完成 = 两个新便携目录/归档可定位、实际冻结诊断通过、旧 S3 保留、版权文件齐备、用户有明确启动入口、范围与证据一致。不存在干净机器时明确未验证跨机器运行、签名及安装器；不把本机通过扩大为所有 Windows/GPU 兼容。
