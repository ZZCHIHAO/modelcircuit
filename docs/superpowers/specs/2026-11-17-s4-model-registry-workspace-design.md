# S4 模型族扩展与工作区恢复设计

日期：2026-11-17。承接已接受的 A3/B3 与基础目录；用户已授权“推进下一步”，并明确主流模型应包含或允许扩展。本轮继续原生 DearPyGui 桌面开发。

## 用户追加：以硬件容量决定模型执行

2026-11-17用户明确“代码理论上不应该有参数上限，只有硬件上限”。以下追加覆盖本文及原计划中“本轮不抬20M、VGG19/ResNet34不支持”的新功能限制；这些段落作为原始决策和已验收M1历史保留，不能继续当作目标约束。

新架构使用`hardware-v5`，参数量、单张量和累计执行元素没有固定数值天花板。结构编辑、形状推导、JSON芯片和Python导出不探测硬件、不分配权重；有限文件/图节点/递归/解析工作量约束继续独立存在。旧v1–v4策略、模型摘要、checkpoint和Python黄金契约保持可读及原行为，用户可通过明确应用新策略升级。

执行前在worker内查询选定CPU或CUDA设备的实际可用容量，分开报告参数、梯度、优化器、BN buffers、激活/采集、临时计算和主机checkpoint/恢复副本成本。参数/已知必需存储最低需求超过实际可用容量时，在分配前给出明确诊断。峰值估计和安全余量存在不确定性，只作预警，不能把保守估算误称精确硬件上限或另一个参数天花板。硬件查询失败需清楚报错；不回退到别的设备。真实分配仍可能受并发负载、碎片和算子workspace影响，OOM应成为可读运行失败；不承诺所有内存错误都能阻止操作系统终止进程。

新Python profile为`vision-pytorch-v5`，字面策略和精确批次guard与静态导入延续源码优先；独立导出依赖PyTorch实际分配器，不承诺复制平台全部内存估算器。硬件观察和容量报告属于运行结果，不能写入图语义/模型摘要。

新模型目录扩展为14项：ResNet18/34/50主干及标准分类器，VGG11/13/16/19标准卷积特征加GAP读出，SqueezeNet1_0/1_1主干及标准分类器。ResNet50使用标准bottleneck及2048维特征。新增跨旧20M的模型必须有静态/独立数值/梯度/状态/Python证据；不只修改菜单。原版VGG大FC、ViT等仍需独立模型/算子支持，解除资源天花板本身不代表自动实现它们。

本地包支持v5；同一batch契约下，hardware-v5工程可以接纳vision-v4芯片而保持工程v5策略，避免添加旧功能芯片后悄悄降回固定阈值。旧包内容不改写，放置时用父工程策略验证等价算子闭包，仍保留独立实例/显式共享和原子撤销。

## 范围与设计取舍

本轮交付两条独立能力：实际可用的多模型族组件和 v3 工作区恢复。只增加 ResNet18 无法满足扩展诉求；一次引入多个外部框架则无法在当前 2D 算子、训练和资源契约下证明可用。因此选择通过现有受支持算子搭建可展开的标准模型族，配合已有有限 JSON 芯片包的本地目录入口，新增模型无需改 UI 或运行核心。

原规格 `2026-11-15-s4-workbench-components-design.md` 的资源、算子、Python 和原生交互契约继续成立。本补充扩大 A4/A5 的实际模型族范围；原先列出的 ResNet34/50、ViT、U-Net、3D、文本和大模型不变成占位可用项。后者列出明确接入条件。20M 参数等硬上限不抬高，也不缩窄标准模型冒充原版。

## 模型能力与扩展

1. 标准 ResNet18 主干/分类器，沿用 A4 stem→stage→block→projection 层级和独立参考验证；1 通道为明确结构变体。
2. VGG11/13/16 的标准卷积特征主干及 GAP512 特征输出，可选具名特征图输出。VGG19 标准卷积特征部分即有20,024,384参数，超过当前20M上限，本轮不列入目录。原版全连接分类器不在本轮支持范围；不以派生小头冒充标准 VGG 分类器。
3. SqueezeNet1_0/1_1 的 Fire 层级主干及标准分类头，保留原版池化、拼接、Dropout、卷积分类头、ReLU 和全局池化语义。加上前述模型，共九个模型/主干目录入口，变体分别构造核查，不能用相似网络顶替已命名标准网络。
4. 注册层独立于 Torch/DPG，以稳定 ID、模型族、输入/输出、配置字段、能力、初始化/权重说明、资源需求描述实际可建模型。目录调用统一构建入口；新增原生图工厂不需要改运行/Python 核心。配置错误、未知模型和不支持的权重配置明确拒绝。
5. 原有 JSON 芯片包继续作为外部扩展边界：只导入受支持算子的架构闭包，结构可展开，支持已有 Python 往返；不执行用户目录中的 Python。界面提供“本地芯片”入口，展示真实包并明确刷新、损坏文件诊断和当前工程导入/放置结果。已有包版本、资源策略、原子插入与冲突改名契约不变。
6. 模型信息明确“随机初始化、无预训练权重”，不自动下载权重或依赖；不能将预训练、通用 ONNX/任意 Python 或第三方模型运行称为已经支持。

默认配置采用能通过当前预算的合理尺寸和批次。超预算时显示具体限制并拒绝，不擅自改变配置。目录只声明已由真实结构、前向、反向、一步更新、状态和代码往返证据支撑的能力。

## 工作区恢复（B4）

沿用原 B4 格式和完整验收要求：`read_workspace_full` / `load_saved_workspace_full` 三返回值；旧两返回值 API 保持兼容；`workspace_payload/save_workspace(..., workbench=None)` 缺省继续 v2，新 UI 始终保存 v3，包括输入无效时的自动/退出保存回退。`NativeWorkbench(..., *, workbench_payload=None)` 恢复经过模型引用净化的有限视图载荷。

v3 保存页签目标、调用路径、选择、探针端口、单/左右/上下布局、面板归属和焦点。没有 DPG 句柄、令牌、张量、源码或任意路径；精确 pan/zoom 不在本轮声明。损坏视图重置并告警但保留有效模型/实验；不支持的工程版本、无效 JSON 和读写失败沿用保护策略，失败读取的原件不得随后自动覆盖。模型替换使旧事件令牌失效，旧源码草稿/测量保护保留；已知错误/探针位置使用真实作用域导航。

## 验收证据

- 工厂/注册/本地包定向测试先红后绿；对非法配置、资源越界、共享/独立实例、名称冲突和文件损坏有行为断言。
- ResNet18 独立手写 Torch 参考与实际平台：224 batch2 eval，32 batch2 train，输出/输入梯度/参数梯度/一步 SGD/BN buffers；11,689,512 是标准 3 通道 1000 类参数验收值。完整图闭包和 Python 有/无 metadata 往返、严格状态映射单列。
- 其他实际模型族至少代表性配置的独立参考前向、梯度、一步更新、状态和 Python 对照；变体逐项结构和预算检查。CPU/CUDA 覆盖范围如实记录，不将微型验证等同科研性能。
- B4 使用实际保存/重新打开/重启恢复及原生 callback/framebuffer，证明页签/布局/选择可用；无效表单自动保存、异常和旧格式回归必须覆盖。
- 完整 backend/native 回归、任务独立审查和整轮交叉审查后关闭本轮。保留原程序/EXE/ZIP、Git index 和原始审查证据，不提交、推送、安装或下载。

## 后续接入边界

ResNet34/50 等大模型须先设计显式资源档位/许可和逐模型预算，不能使用现在的 20M 档位假称支持。MobileNet/EfficientNet 需相应激活/SE/算子语义；ViT/Swin 需 token/reshape/attention 等契约；U-Net/检测需上采样/任务损失/标注和评估；3D 需空间几何及 3D 算子；文本/LLM/RAG 需各自端口类型、状态、执行和评价后端。这些扩展共享注册/组件/工作区接口，但不强行套用现有分类训练循环。
