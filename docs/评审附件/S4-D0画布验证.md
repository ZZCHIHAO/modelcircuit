# S4 D0 原生双画布能力验证

验证日期：2026-11-16。环境：Windows、仓库 `studio/.venv/Scripts/python.exe`、Dear PyGui 2.3.1。范围是独立原生诊断，不改生产工作台。

结论：本机可以常驻两个真实 node editor，并在应用回调、原生对象身份与布局层面隔离。可以继续设计 CanvasHost，但不能据此宣称真实鼠标手势完整验收，也不能承诺精确 pan/zoom 或原生选择位恢复。

## 公开 API 核查

以本机 `inspect.signature`、`dir(dearpygui.dearpygui)` 及真实 editor 的 `get_item_configuration` 为主要依据。原始完整签名保存在 JSON 的 `api.signatures`，包括：

| 接口 | 本机观察 |
|---|---|
| `add_node_editor` | 公开提供 `parent`、`callback`、`delink_callback`、`show`、尺寸和 `minimap/minimap_location` |
| `add_node` / `add_node_attribute` | 节点公开 `pos`，端口公开 `attribute_type`，可分配独立 tag |
| `add_node_link(attr_1, attr_2, ..., parent=...)` | 指定两个真实端口和所属 editor |
| `get_selected_nodes(node_editor)` | 读取 editor 的原生节点选择 |
| `get_selected_links(node_editor)` | 读取 editor 的原生连线选择 |
| `clear_selected_nodes/clear_selected_links(node_editor)` | 清除原生选择；本轮只验证空状态调用 |
| `get_item_pos` / `set_item_pos` | 读取/修改节点布局；不是画布 pan/zoom |
| `get_alias_id` / `get_item_info` | 验证真实对象身份及所属父 editor |
| `set_viewport_resize_callback` / `configure_item` | 应用在同一 UI 线程调整 viewport 和双 pane 尺寸 |
| `output_frame_buffer` | 生成应用自身画面证据 |

未在本机公开函数清单、editor 签名与配置键中找到 node editor 的 pan/zoom 精确读写，也未找到原生节点/连线 selection setter。清单中的 plot axis zoom API 属于 plot，不可替代 node editor；item scroll 同样不用于本验证。DPG 文档的 node editor 说明仅作公开背景，不能替代本机版本证据：`https://dearpygui.readthedocs.io/en/latest/documentation/node-editor.html`。

DPG 可能在公开查询中保留 alias。例如本轮 `get_item_info(link)['parent']` 返回 `d0_root_editor`，解析后才得到真实原生 ID 33。测试和诊断均通过 `get_alias_id` 解析后比较；没有仅比较 tag 字符串。

## 实际验证

两个 editor 均包含 `call:shared`、`call:next` 这两个同名模型引用，但 DPG tag 带各自 scope 前缀，节点、端口和链接为不同的真实对象。独立 `Document` fixture 的根图和芯片定义也具有同名调用。

| 对象 | root 原生 ID | chip 原生 ID |
|---|---:|---:|
| editor | 33 | 51 |
| `call:shared` 节点 | 34 | 52 |
| `call:next` 节点 | 41 | 59 |
| 输出端口 | 37 | 55 |
| 输入端口 | 42 | 60 |
| link | 67 | 68 |

上述值来自独立诊断该次 context，不是跨会话稳定 ID。single 隐藏 chip、columns 显示双栏、rows 显示上下栏及 viewport 从请求 1240×860 调整为 1100×780 后，这些原生 ID 全部一致。JSON 保留每个阶段的 ID 与实际 editor 尺寸。columns 的两个 editor 均为 580×676；rows 均为 1186×301；single 中隐藏 editor 的矩形为 0×0，但其对象仍存在。

通过从真实控件读取注册 callback 和 user_data 再调用的方式，验证了：

- 连线使用数值原生端口 ID；sender 支持真实别名与数值 ID，并解析到所属 editor。
- 每个 editor 的连线均创建在本 editor 下；跨 editor 端口、反向输入/输出端口组合、跨 editor 删线均由应用路由明确拒绝。
- 删除 root 的 link 后，chip 的 link 仍存在。此删除发生在身份比较完成之后，JSON 中明确标记比较阶段。
- root 的逻辑选择为 `call:shared`、chip 为 `call:next`；非明确意图的空选择保留逻辑选择，root 的明确清除回调不改变 chip。主题高亮仅表示逻辑选择。
- `get_selected_nodes/get_selected_links` 均直接调用公开 getter，没有 mock、赋值或伪造返回值。本轮两 editor 的原生选择均为空，因此不能据此声称原生正选择或恢复成功。
- 先由公开 `set_item_pos` 把 chip 的 `call:shared` 移到 `(87,134)`，再调用真实“Commit node positions”按钮 callback，从原生 `get_item_pos` 读值并执行现有 `Document.move`。芯片定义的坐标改变，根图同名节点保持 `(30,40)`；Document 的语义摘要和 revision 均不变，原导航 cursor 恢复。
- 节点中的真实“Open shared reference”按钮 callback 携带 chip 的 view/ref；这验证导航回调归属，不等同于双击输入投递或 hit test。
- minimap 在两个真实 editor 中配置为 true，三个 framebuffer 均能看到对应 minimap；不能由配置或截图推断 minimap 鼠标导航正确。

## 能力矩阵与边界

| 能力 | 状态 | 限定 |
|---|---|---|
| 两个常驻 editor | 支持，已验证 | 独立 tag、不同原生 ID |
| single/columns/rows 与 resize | 支持，已验证 | 应用自身按钮/viewport callback，同一 UI 线程 |
| editor/节点/端口/link 身份保持 | 已验证 | hide/show 与尺寸变化；不删除重建 editor |
| 本 editor 连线与跨 editor 拒绝 | 已验证 | 应用注册 callback 层；没有发送物理鼠标手势 |
| 对应 Document scope 的布局更新 | 已验证 | 公开位置读写和应用按钮 callback；没有冒称真实拖动 |
| 独立逻辑选择与主题高亮 | 已验证 | 与原生 ImNodes 选择位分开 |
| 原生 selection get/clear | 公开存在，空状态已验证 | 正选择后的 clear 效果待真实输入实测 |
| 原生 selection setter/精确恢复 | 无公开支持 | 不能把逻辑高亮当作原生恢复 |
| 精确 pan/zoom 读写与恢复 | 无公开支持 | 不能承诺跨重建或跨会话恢复；非零平移后的会话保持也未测 |
| minimap 渲染 | 已验证 | minimap 鼠标导航待实测 |
| 真实节点拖动、连线手势、双击命中 | 未验证 | 未使用电脑控制、OS/浏览器输入自动化或注入输入 |
| 生产 CanvasHost、事件版本令牌与完整工作台 | 不在本关口范围 | B1/B2 需要各自实现与回归 |

## 生命周期与后续约束

诊断只调用一次 `create_context` / `create_viewport`，设置手动 callback 队列后 setup/show，并在同一线程渲染。正常完成和测试退出均通过 context manager 的 `finally` 调用 `destroy_context`；构建异常也销毁 context。报告在退出销毁后写入最终 `context_destroyed=true`。没有后台 worker、训练任务或依赖安装。

本关口没有观察到双 editor 之间的原生对象污染。B2 可以继续采用常驻 editor、局部映射、明确事件 owner 与原生 ID 对照。精确 pan/zoom 和原生选择恢复保持“不支持”的公开契约；真实鼠标交互保留为后续人工/允许方式验收项，不因本轮测试通过而抹去。
