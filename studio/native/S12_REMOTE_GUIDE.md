# S12 多卡训练与远程执行

`v0.9.3-alpha.1` 在同一个 Windows 桌面版提供本机 CPU、CUDA 单卡和 Linux 服务器 CUDA DDP。远程首批任务为 ImageFolder 图片分类。

## 开始一次双卡训练

1. 在「实验」配置并核对本机 ImageFolder 数据与模型，从「工程」导出科研工程。服务器端准备与工程数据锁匹配的目录，保持相对路径、文件内容和划分一致。
2. 在「实验」点「服务器多卡…」。填写系统 OpenSSH 已配置的主机别名、服务器 Python 的绝对路径、远程可写工作目录。已授权的 Linux 环境应能运行带 CUDA 和 NCCL 的 PyTorch，以及项目依赖。桌面连接使用已有 SSH 密钥和已核对的主机密钥。
3. 点「连接并读取显卡」。勾选已分配给你的显卡，查看每张卡的物理编号、显存占用和计算利用率。程序按 UUID 绑定设备。选择每卡批次、梯度累积次数和目标轮数。
4. 选择本地 `project.json` 或使用已在工程页打开的工程，填写服务器 ImageFolder 根目录，点「启动多卡训练」。工程的模型、设置和数据锁随作业提交，原始图像直接从服务器目录读取。
5. 在底部「远程作业」查看进度与日志。桌面重启后，连接服务器会按保存的任务 ID 恢复跟踪。也可以输入旧任务 ID 手动查询。
6. 点「停止」后，状态会在训练进程结束时变为「已停止」。至少完成一轮后才有续训检查点。保持同一个工程、数据、显卡和批次设置，将目标轮数设为大于已完成的轮数，再点「从检查点续训」。续训生成新的任务 ID。
7. 任务完成后点「下载并打开结果」。桌面校验运行报告和产物摘要，在「工程运行记录」显示 DDP 卡数、有效全局批次、曲线、测试指标和权重。

两张卡每卡 2 个样本、梯度累积 2 次时，每次更新使用 8 个样本。为使各进程更新次数一致，训练每轮按固定种子重排样本并舍弃不足一个有效批次的尾部，报告记录舍弃数量。验证集按样本汇总。测试集覆盖完整划分，使用验证损失选出的最佳权重。

## 环境与范围

- 本机 CPU 和 CUDA 单卡按原有实验配置运行。S12 的多卡入口为单台 Linux 主机的 NCCL DDP。
- 服务器需已有能运行 ImageFolder 分类的 Python 环境。首批验收使用 Python 3.10 和 PyTorch 2.5.1 CUDA 12.4。连接时会同步对应版本的工作进程源码，服务器工作目录的上一级需已存在。
- 作业、检查点和日志保存在所选服务器工作目录。一个作业目录内的运行记录可用任务 ID 找回。显卡锁覆盖同一远程作业根目录，提交时还会检查所选卡的活动计算进程。
- 构建使用 `./studio/build-s4-desktop.ps1 -Stage S12`。本机工作区继续使用 `%LOCALAPPDATA%\ModelCircuitStudio-S10`。
