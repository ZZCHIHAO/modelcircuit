# S4 多模型、硬件容量与工作区使用指南

日期：2026-11-17。本文件面向已通过整轮审查的原生桌面源码里程碑；验证范围见[验收记录](../../docs/评审附件/2026-11-17-S4-多模型与硬件工作区验收记录.json)和[验证说明](S4_MODELS_WORKSPACE_VERIFICATION.md)。旧便携EXE/ZIP仍为S3，不包含这些新增功能。

## 启动与模型库

双击项目的 `studio/启动S4源码预览.cmd`；使用已有CUDA环境时双击 `studio/启动S4-CUDA源码预览.cmd`。两者使用不同的用户状态目录，不安装依赖或下载模型。

左侧目录支持中文/英文搜索，选择“视觉主干”或“完整模型”，点击“配置”后添加，或者直接将组件拖到目标画布。完整名称、端口和默认参数在tooltip与配置窗显示；长结果列表可以独立滚动。

| 模型族 | 实际可放置项 | 默认输出 |
|---|---|---|
| ResNet18、34 | 每种各有主干和标准分类器 | 主干features `[N,512]`；分类器logits `[N,K]` |
| ResNet50 | 主干和标准bottleneck分类器 | features `[N,2048]`或logits `[N,K]` |
| VGG11、13、16、19 | 标准非BN卷积特征＋GAP读出 | features `[N,512]`，可选featuremap |
| SqueezeNet1.0、1.1 | 每种各有Fire主干和标准分类器 | features `[N,512]`或logits `[N,K]` |

共14个模型入口、36个内置组件（另含17基础算子和5功能芯片）。模型内部可展开，仍使用普通芯片/算子，不是不可编辑的图片。VGG项目不包含原版大FC分类器；GAP512读出在名称中明确标出。SqueezeNet分类头保留Dropout→1×1卷积→ReLU→GAP→Flatten。

全部模型目前是平台默认随机初始化，没有预训练权重。标准拓扑及加载同一状态后的数值一致，不表示与torchvision相同seed的初始化权重相同。支持1/3通道；1通道明确是结构变体。

## 从真实图片开始训练

1. 在实验面板选择ImageFolder，指定分类文件夹和划分方式，检查数据、类别数、通道和尺寸。分类划分使用现有泄漏检查，不以训练损失代替验证/测试。
2. 可先从已检查数据创建起始模型以获得匹配的数据输入和logits输出。使用成熟模型时删除旧的中间网络调用，保留需要的输入/输出接口，再放置分类器。
3. 例如选择ResNet50分类器，将 `input_shape` 设为 `[null,3,224,224]`，`num_classes` 设为数据实际类别数。尺寸/通道须与数据检查结果完全一致。
4. 连接“数据输入→分类器x”和“分类器logits→工程logits”，点击校验。也可用主干features连接MLP头；ResNet50的头输入维度为2048，其余上述主干为512。
5. 新模型默认 `resource_profile="hardware-v5"`、`resource_batch_bound=2`。这是本次图的明确批次契约。实验面板先将batch设为2，再选择CPU或实际可用的 `cuda:N` 并运行；平台不自动修改实验batch。若需要更大批次，在放置配置时显式改变契约并重新校验。
6. 查看训练损失、验证选优、测试评估、checkpoint与探针。当前执行仍是单个CPU或单张选定GPU；未实现多GPU并行。

32像素、batch1的ResNet训练可能因BN最后阶段只有一个观测值而报错，这是BN训练条件；不能把降低batch当作所有模型的通用修复方式。成熟架构适用的数据尺度、训练协议和评价仍由研究者选择。

## 没有人为参数数量天花板

hardware-v5不设置固定参数量、单张量元素或累计执行元素上限。ResNet34、ResNet50和VGG19可以超过原先20M阈值。编辑、形状校验、架构保存和Python导出不要求本机装得下整个模型，也不创建权重。

执行前才查询所选设备的可用容量。CPU核对可用物理内存及提交余量，CUDA核对选定ordinal的可用显存，并分别考虑CPU暂存/数据/检查点副本。当前模型和估算均按float32；AMP、量化和分布式内存策略尚未实现。

运行报告区分参数、梯度、优化器、BN buffers、输入、激活、采集、临时计算和主机状态副本。已知必需存储下界超过可用容量时在分配前拒绝；保守峰值加余量只作预警。实际峰值受算子workspace、碎片和其他进程影响，预检查不保证一定不会OOM。运行产物中的 `memory_report` 保留查询与估算，硬件观察不改变模型摘要。

本轮微型GPU数值验收固定初始化种子、关闭TF32，并开启cuDNN deterministic；未放宽输出或梯度容差。默认训练没有被强制改成该验收设置，不保证GPU默认执行或checkpoint恢复位级一致，也不提供性能结论。

旧工程继续保留原执行策略。需要解除历史阈值时点击左侧“硬件容量策略…”，检查说明后确认；修改可撤销，实验设置不变，但checkpoint兼容身份会改变。旧无显式批次契约的工程使用64，已有契约则保留。添加新模型也会在策略不匹配时请求显式采用。硬件工程接纳旧合法芯片时保持硬件策略，不因加入旧融合头降回固定参数阈值。

文件大小、图节点数、递归深度和解析工作量仍有保护边界。这些限制用于保持编辑器和解析器可响应，不能被描述为模型参数数量上限。

## 自定义“芯片”和扩展模型

普通使用者：搭建受支持算子/芯片，指定具名输入输出和公开参数，在“接口与芯片→版本与本地芯片库”保存版本。保存后左侧本地芯片目录立即刷新；外部复制的JSON架构包放到该源码预览状态目录的 `chips` 子目录，再点击“刷新本地芯片”。刷新按钮tooltip显示实际目录。

本地包只包含架构闭包及策略，不包含权重，不执行旁边的Python。损坏文件单独提示；可用文件仍显示。目录每次最多读取排序靠前的64个JSON文件、合计16MiB，单文件4MiB，目录扫描512项。大于单文件限制的文件在读取前跳过，不占读取预算。相同内容去重；拖放使用已校验的版本快照，文件变更后须刷新。

放置生成独立实例；“添加共享调用”才显式共享同一实例的参数。内部定义编辑会影响引用该定义的实例；关闭页签不会删除芯片。资源契约不同会明确提示，取消保持原工程。

开发者还可以编写纯JSON图工厂，返回 `ComponentBundle`，用 `ModelSpec` 声明端口/配置/能力并通过 `DEFAULT_MODEL_REGISTRY.with_model(spec, factory)` 扩展独立注册表。目录API的 `registry=` 和桌面构造参数 `NativeWorkbench(..., model_registry=registry)` 使用同一注册表；不需要修改画布、训练运行或Python生成核心。该接口用于受信任的本地开发代码，平台不会自动发现或执行任意Python插件。

超出现有算子的模型需要实现算子/形状/执行/代码往返及对应任务后端。解除参数上限不会自动实现MobileNet/EfficientNet所需激活、ViT/LLM注意力、3D、分割、检测或文本生成协议；这些模型也不会以假可用组件出现。

## 工作区、Python和探针

保存JSON会写v3工作区，包含模型、实验及页签/调用路径/选择/探针端口/单栏左右上下布局/焦点。重开和启动恢复会还原这些有限状态。旧v2与纯图仍可读；视图不会改变模型或checkpoint身份。

损坏视图可以回到根视图并保留有效模型/实验，源文件会受自动保存保护；显式保存才确认修复后的结果。无效JSON、未知工程版本或读取失败会备份并保护原件。临时无效表单自动保存采用上次有效实验设置，并继续保存v3视图，不清空Python草稿或旧测量。

Python v5保留hardware策略和批次guard。平台生成代码支持可靠往返；约定范围的源码修改优先于旧visual metadata。删除元数据仍可还原支持的结构/共享关系，不能承诺恢复已删除的版本/布局身份。任意第三方Python不保证无损导入。独立导出程序依靠PyTorch实际分配器，未复制平台完整硬件估算器。

探针显示真实采集来源，可以跳到已知调用路径和端口；缺少采集数据时显示未采集。当前采集有数量/预览预算，不能把可见探针当作所有内部张量、梯度和科学有效性的完整证明。精确跨会话pan/zoom、人手拖拽手势认证、新EXE、远程和多GPU不在本轮保证范围。

## 源码与官方规范

- 图工厂：`studio/backend/studio_core/backbone_templates.py`；声明/扩展：`model_registry.py`；统一目录：`component_catalog.py`。
- 资源策略：`schema.py/execution_policy.py`；硬件与估算：`devices.py/memory_admission.py`；运行：`runtime.py/classification_runtime.py`。
- 原生目录/本地库：`studio/native/catalog_panel.py/local_components.py/chip_library.py`；保存恢复：`workspace_state.py/workbench_state.py`。
- 独立参考、命名状态映射及设备验证工具在 `studio/backend/tests/`；原生回调/截图脚本在 `studio/native/tests/`。
- 模型拓扑核查使用官方 `pytorch/vision` 的固定 `v0.21.0` 标签下 `torchvision/models/resnet.py`、`vgg.py`、`squeezenet.py`，核查日期2026-11-17；URL/原始字节SHA256/git blob SHA保存在可携带验收记录的官方来源索引中。没有下载模型权重或增加torchvision依赖。
